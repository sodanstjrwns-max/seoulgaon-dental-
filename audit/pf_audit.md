# 1부. 평가 체계 전체 설명 (6영역 · 37항목 · 100점)

Patient Grader는 "AI가 병원을 추천하는 시대에, 이 홈페이지가 검색엔진·AI·환자 세 독자 모두에게 얼마나 잘 읽히고 설득하는가"를 측정합니다.

| 영역 | 이름 | 배점 | 측정 대상 |
|---|---|---|---|
| A | 크롤 가능성 | 15점 | 검색엔진·AI 크롤러가 사이트에 접근하고 색인할 수 있는가 |
| B | AI 가독성 | 15점 | 기계가 병원 정보를 구조적으로 이해할 수 있는가 |
| C | 콘텐츠·E-E-A-T | 20점 | AI 인용·검색 노출을 만들어내는 콘텐츠 자산의 질과 양 |
| D | 사람의 눈 (후킹·카피·설득력) | 20점 | 환자가 읽었을 때 이 병원을 선택할 이유가 보이는가 |
| E | 전환 거점 | 15점 | 방문자가 예약·문의로 넘어가는 동선이 열려 있는가 |
| F | 기술 현대성·페이지 경험 | 15점 | 홈페이지의 기술적 연식·속도·보안·접근성 |

## A. 크롤 가능성 (15점) — "문이 열려 있는가"

| ID | 항목 | 배점 | 무엇을 보는가 · 만점 기준 |
|---|---|---|---|
| A1 | 검색·AI 크롤러 개방성·최적화 | 4 | robots.txt가 검색봇과 AI 크롤러(GPTBot·ClaudeBot 등)를 차단하지 않는가. 만점은 AI 크롤러 명시 허용 + llms.txt(AI용 안내 문서)까지 |
| A2 | sitemap.xml 존재·유효·규모 | 4 | sitemap이 존재·유효하고 등록 URL이 충분한가. **규모 기준: 상위권 1,500 URL+**. 수백 개 수준이면 "색인 자산이 작다"로 감점 |
| A3 | lastmod 정직성 | 1 | sitemap의 수정일이 실제 수정일인가. **전 페이지가 같은 최근 날짜면 "거짓 lastmod"로 0점** — 구글은 거짓 날짜를 반복하는 사이트의 날짜 신호 전체를 무시함 |
| A4 | canonical 정합성 | 2 | www/비www·http/https가 대표 URL 하나로 수렴하는가. 도착 URL이 2가지 이상이면 평가 신호가 분산되어 감점 |
| A5 | 응답 건전성·속도 | 4 | 서버 응답 코드 건전성, 깨진 링크, 응답 속도 |

## C. 콘텐츠·E-E-A-T (20점) — "AI가 인용할 답이 있는가"

| ID | 항목 | 배점 | 무엇을 보는가 · 만점 기준 |
|---|---|---|---|
| C1 | 원장 실명·이력의 텍스트 존재 | 2 | 원장 실명·이력이 이미지가 아닌 텍스트로 존재하는가 (E-E-A-T의 권위 신호) |
| C2 | 질문형 콘텐츠 (팬아웃 대응) | 3 | AI는 "OO 임플란트 잘하는 곳" 질문을 수십 개 세부 질문으로 쪼개 검색(팬아웃)함. 환자가 실제 묻는 질문("임플란트 얼마나 아픈가요")을 제목으로 한 페이지 수. **상위권 기준 질문형 제목 20개+** |
| C3 | 첫 두 줄 직답 구조 | 3 | AI 발췌(스니펫)는 첫 두 줄에서 결정됨. 콘텐츠 5건 표본의 직답률로 판정: **직답률 60%+ → 3점 / 40%+ → 2점 / 20%+ → 1점**. "안녕하세요, 원장입니다" 서론 시작은 0점 처리. ※치료사례 페이지는 표본에서 제외(사례는 C4·C7로 평가) |
| C4 | 경험 신호 (첫 번째 E) | 3 | E-E-A-T의 Experience. 교과서적 일반론이 아닌 **실제 진료 장면 묘사**("30대 직장인이 의자에 앉자마자 물었습니다…")가 있는가. 장면 0개=암시 신호만 있으면 1점, 1개=2점, 여러 개=3점 |
| C5 | 신선도 | 2 | 최신 콘텐츠 발행일. 의료(YMYL)는 신선도가 신뢰 신호. 60일+ 경과 시 감점 |
| C6 | 지역 신호 | 2 | 동 단위 지역어("구월동", "명지동")의 자연스러운 반복 — "OO동 치과" 질문 대응력 |
| C7 | 콘텐츠 자산 규모·깊이 | 5 | AI 인용은 확률 게임 — 답이 될 페이지가 많을수록 인용 확률 상승. **만점 기준: 콘텐츠 유형 4종+(백과사전·칼럼·치료사례·FAQ·블로그 중) × 충분한 물량, sitemap 1,500 URL+ 급**. 1~2유형 몰빵이면 물량이 커도 감점 |

## D. 사람의 눈 — 후킹·카피·설득력 (20점) — "환자가 읽고 움직이는가"

| ID | 항목 | 배점 | 무엇을 보는가 · 만점 기준 |
|---|---|---|---|
| D1 | 3초 테스트 (퍼스트뷰 정체성) | 4 | 첫 화면 3초 안에 ①무슨 진료과 ②어느 지역 ③주력이 뭔지 즉답되는가 + **주력의 구체 증거(수치·고유명사) 2개 이상** |
| D2 | 주어 테스트 (병원 자랑 vs 환자 문제) | 3 | 헤드라인의 주어가 병원("저희는")인가 환자("당신의 문제")인가. **환자 주어 비율 50%+ → 3점 / 25%+ → 2점 / 10%+ → 1점 / 미만 → 0점** |
| D3 | 클리셰 지수 | 3 | **"병원 이름을 옆 병원으로 바꿔도 성립하는 문장"의 비율** (룰 사전 + LLM 문장별 판정 하이브리드). 교체가능률 25% 이하 → 3점 / 45% 이하 → 2점 / 65% 이하 → 1점 / 85% 이하 → 0.5점 / 초과 → 0점. "환자 중심·정직한 진료·맞춤 진료·편안한 진료·첨단 장비·풍부한 경험"이 대표 클리셰 |
| D4 | 구체성 지수 | 3 | 실적 수치와 고유명사의 조합. **만점 = "케이스 수 + 브랜드/장비 실명"이 함께 있을 때**. "30년 전통"은 오래됐다는 사실이지 잘한다는 증거가 아님 |
| D5 | 전문용어 장벽 (환자의 언어) | 2 | 치조골·골유착·지대주·상악동 등 전문용어가 환자 언어 병기 없이 노출되는가. 환자는 "잇몸뼈가 녹았대요"로 검색하고, AI도 환자의 언어로 질문받음 |
| D6 | 공포 마케팅 감지 | 2 | 공포 조장형 카피("지금 안 하면 큰일") 존재 여부 — 없어야 만점 |
| D7 | 사회적 증거의 존재와 신선도 | 2 | 후기·리뷰·사례 등 사회적 증거의 존재와 최신성 |
| D8 | 읽기 피로도 | 1 | 300자+ 벽텍스트 블록 수와 평균 문장 길이. **기준: 문단당 2~3문장, 문장당 60자 이내** |

# 3부. 병원별 상세 감점 카드 (점수 내림차순)

각 항목은 엔진이 실제 출력한 **진단(왜 깎였나)** · **증거(무엇이 검출됐나)** · **처방(어떻게 고치나)** 원문입니다.


## 1. 서울비디치과 (bdbddc.com) — **93.5점** (감점 합계 -6.5)

### [-2점] D3 클리셰 지수 (1/3)
- **진단**: 홈페이지 문장의 약 65%는 병원 이름을 지우면 어느 병원인지 알 수 없는 문장입니다. 판정 대상 20문장 중 13문장(65%)이 병원 이름을 바꿔도 성립하는 문구입니다.
- **증거**: 클리셰 사전 매칭 4건: "환자 중심", "정성을 다하", "맞춤 진료", "정직한 진료"
- **증거**: "이건 안 해도 돼요" 라고 솔직히 말하는 치과
- **처방**: 클리셰를 구체 사실로 교체하세요. 예: "풍부한 경험" → "임플란트 3,200케이스" / "첨단 장비" → "장비 모델명 + 그걸로 뭘 다르게 하는지".

### [-1.5점] F3 성능 (Core Web Vitals) (3.5/5)
- **진단**: 속도가 평범합니다. 모바일 3G 환경의 환자를 기다리게 하고 있습니다.
- **증거**: PageSpeed 측정 불가 — 서버 응답시간 기반 근사 판정 (중앙값 0.0초, 참고치)
- **처방**: (엔진 처방은 유료 리포트 잠금 — 아래 공통 처방 참조)

### [-1점] C4 경험 신호 (첫 번째 E) (2/3)
